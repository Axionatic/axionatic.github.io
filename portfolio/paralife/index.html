One writer, a thousand readers

  • Ordered event stages mutate the world — simulation, environment, actions, then broadcast
  • Every world mutation happens on the tick thread, so the grid needs no contended locking
  • Each connection owns one virtual thread draining a bounded queue — the tick never waits on a socket
  • 1,000 sessions sustained in 45 ms of a 500 ms budget

The deadlock that taught me Loom

  • A cell index took its own monitor, then blocked on the world read lock
  • A virtual thread blocking inside synchronized pins its carrier — it cannot unmount
  • Mass idle-timeout at fleet teardown starved every carrier and hung the server for two hours
  • Fixed by swapping the monitor for a ReentrantLock, then proven with JFR captures and a 44-run stress sweep pinned to two cores

Slow clients don't get to win

  • Each session drains a bounded 128-frame queue; overflow marks the session stalled rather than blocking the tick
  • The entity stays on the grid for a ten-tick grace window instead of dying instantly
  • A resume token lets the client reconnect and rebind to the same entity
  • Fire-once guards mean the transition happens at most once per attach, however noisy the socket

Proving a rewrite changed nothing

  • Replacing full-grid scans with sparse-set iteration had to be provably behaviour-neutral
  • A digest of every byte sent to every session is captured before and after
  • The rewrite is only accepted if all per-session digests are byte-identical
  • A vacuous-baseline guard asserts no digest matches the hash of empty input
