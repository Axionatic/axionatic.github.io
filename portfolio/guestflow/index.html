Architecture

  • The server handles only what needs auth. The rest is edge-cached
  • Guesty allows 5 tokens a day, so two cache tiers absorb cold starts
  • Zod guards every boundary — Guesty's payloads diverge from its docs
  • Signed webhooks sync on change. Permanent errors return 200, not a retry storm

Proof of payment

  • Two payment rails, GuestyPay and Stripe, behind one interface
  • Card data never touches the server. The payment SDK holds it
  • A created reservation isn't proof. Pending counts as a failure
  • Unpaid holds cancel themselves, but only for allow-listed platforms

One Worker per client

  • Every client gets its own Worker, its own secrets, its own cache
  • Isolation is structural, not a WHERE clause someone can forget
  • CI ships an allow-listed snapshot, so admin code can't reach a client
  • A build test fails if admin code leaks into the client package
