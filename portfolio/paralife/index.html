One writer, a thousand readers

  • One tick thread mutates the world: simulation, environment, actions, broadcast
  • 1,000 readers get an immutable snapshot, not the live grid
  • One virtual thread per connection drains a bounded queue. The tick doesn't touch sockets
  • Stress-tested 2,000 connections: every tick under its 500ms budget

The bug that needed a fleet

  • A cell-index monitor nested under the world read lock: harmless under normal load
  • Stress-test teardown fired 2,000 idle-timeouts at once. Each VT pinned its carrier and the pool starved
  • VTs are built to block, but not while holding a monitor
  • Switched to ReentrantLock. JFR: 0 pinning events in 44 stress runs

Slow sockets, second chances

  • Every session drains a bounded 128-frame queue. Overflow stalls a session, not the tick
  • A stalled entity lives on for a ten-tick grace window
  • A resume token rebinds a reconnecting client to the same entity
  • Fire-once guards: one transition per attach, however noisy the socket
